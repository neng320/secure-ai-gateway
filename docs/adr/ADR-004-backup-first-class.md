# ADR-004: 备份恢复是网关的一等能力（内建，不依赖人工操作）

- 状态：Accepted
- 日期：2026-08-28
- 关联：主方案 P2；ADR-003；storage-layout.md

## 背景

网关 SQLite 中存放 Client 配置、（P1-03 后的）加密 Provider Key、用量记录。文件丢失/损坏 = 全部客户端配置作废。人工复制不可靠、不可验证、无演练。

## 决策

1. 备份内建于 Gateway：`internal/backup/` 提供调度（默认 6h，可 3/12/24h）、快照、manifest+SHA-256、加密、轮转、恢复预检与恢复（P2-01~P2-09）。
2. 备份资产：SQLite 快照 + 非敏感配置 + 策略/版本信息 + key-id；**Provider 主密钥与备份加密密钥绝不与普通备份同包明文保存**。
3. 加密：独立 `BACKUP_MASTER_KEY`（环境变量/secret 文件），无密钥不可读归档。
4. 保留策略默认：近 24h 滚动 + 14 daily + 8 weekly；清理前必须确认至少一份已验证可恢复快照。
5. 恢复流程强制：恢复前自动 emergency backup → 维护模式 → 替换数据库 → integrity_check + smoke → 退出维护（P2-09）。
6. 升级/迁移前强制 pre-upgrade snapshot（P2-10）；每月随机快照隔离目录演练（P8-07），RPO ≤ 6h / RTO ≤ 30min（实测记入 runbook）。
7. 备份目标优先本机第二物理盘/NAS；备份目录与数据库同卷时启动告警（P2-06）。

## 备选方案

1. **外部工具（litestream/rclone cron）**：可用，但恢复路径不受 Gateway 控制、无法做 Admin"Backup Now"与恢复预检 UI（P2-07），验收测试难写；且引入额外运维单元。
2. **不做内建，仅文档化人工流程**：直接违背 V1 安全边界 §2"备份必须可校验、可恢复、可轮转"。
3. **云对象存储为主**：V1 不引入云端依赖（scope-v1 Won't）；本地加密归档可后续由用户自行同步上云。

## 后果

- 正面："文件丢失可恢复"成为可测试的产品能力；恢复演练可自动化进 CI 外的例行运维（P8-07）。
- 负面：Gateway 代码量增加；备份加密密钥管理成为新的运维责任（丢失 = 备份不可用，需在 runbook 中明确提示）。
